I have taken photos of the boxes of the models i own. is there any way to implement image recognition that accurately identifies the model from the picture, cross-reference it with data on scalemates and fill in the details just from the image? if yes, give me the steps. don't start implementing this feature as of now, i just want to know what would need to be done and the steps involved and most importantly, if it would be free and accurate/efficient

Short answer: yes, it's doable, free, and can be quite accurate — but not the way the question is framed. The winning move is to stop thinking of it as image recognition.

## The reframe

A model kit box isn't a thing you recognise visually — it's a thing that has the answer **printed on it**. Brand wordmark, scale in big type, kit number, and almost always an EAN-13 barcode. So this is an OCR and barcode problem, not a computer-vision classification problem. That matters enormously, because the first is a solved problem that runs offline in 200ms, and the second is a fine-grained classification task over ~100,000 classes that you have no training data for.

If you went the classifier route you'd need dozens of photos of each kit box you want recognised, for every kit in existence. Don't.

## What's free and actually works

**Google ML Kit**, on-device, no API key, no quota, no network, no cost. Two analysers, both run on the photo you already take:

- **Barcode scanning** — reads the EAN-13 off the box. This is the strong signal: an EAN identifies exactly one product. Reliability on a reasonably lit photo is near-perfect, and it's the same technology every supermarket self-checkout uses.
- **Text recognition** — returns text blocks with positions. From those you'd pull the scale with a regex (`1/48`, `1:48`, `1-350` — box art essentially always prints it), the brand by matching against a closed list of maybe 50 manufacturers, and a candidate kit number as an alphanumeric token near the brand.

Both are Gradle dependencies (`com.google.mlkit:barcode-scanning` and `com.google.mlkit:text-recognition`) — check the current versions on the ML Kit docs rather than trusting a number from me. Text recognition comes in two flavours: bundled, which adds a few MB to the APK and works immediately offline, or Play-Services-delivered, which keeps the APK small but downloads the model on first use. Given the app is deliberately offline, bundled fits better.

## The part that doesn't work

Cross-referencing against Scalemates automatically. Same wall as before: no public API, and their robots.txt asks automated tools out of search. Reading the EAN off a box is easy; turning it into a kit page is the step the app isn't allowed to take on its own.

Interesting detail though — Scalemates *does* publish the EAN on kit pages. Your own parser test fixture has `EAN: 4950344611195` sitting in the meta description. So the matching key exists on both ends; what's missing is permission to query it in bulk.

The honest options are the one you already built — open their search with the EAN prefilled, you pick the kit, paste the link back — or a paid cloud service. There's no free barcode-to-model-kit database with decent coverage; the general-purpose UPC lookup APIs have tiny free tiers and barely know this niche.

A multimodal LLM could genuinely identify a kit from box art, better than OCR alone. But it means an API key (which you can't safely ship inside an APK), or a backend you run and pay for, plus a network round trip per photo — and it still can't hand you an authoritative Scalemates URL. That's a lot of machinery to replace one paste.

## The shortcut that fits your situation

You're photographing boxes of kits **you've already catalogued**. That changes the problem completely.

Instead of "which of 100,000 kits is this?", it becomes "which of my 46 is this?" — a closed set you already hold in the database. OCR the box, pull whatever tokens you can, fuzzy-match them against your own `name`, `number` and `brand` columns, and pick the best score. On a set that small, with a kit number or even a half-read brand plus scale, that's near-perfect and needs no network at all.

That would make bulk photo work genuinely fast: shoot all your boxes, then let the app match each photo to the right existing kit and attach it, instead of you opening 46 records by hand.

## Accuracy, field by field

- **Scale** — very good. Large type, unambiguous format, trivial regex.
- **Brand** — good. Wordmarks are distinctive and the list of manufacturers is short and closed.
- **EAN** — excellent when the barcode is in frame and in focus; useless when it isn't, since it's usually on a side panel rather than the box top.
- **Kit number** — moderate. Often small, sometimes only on the side, and easily confused with the EAN digits or a copyright year.
- **Full kit name** — poor as free text, fine as a fuzzy match against a known list.
- **Scalemates link** — not automatic, for the reasons above.

Speed is a non-issue: on-device, a few hundred milliseconds per photo, no network.

## If you decide to build it

1. Add the two ML Kit dependencies.
2. After a photo is taken or picked in the add/edit form, run both analysers on the same image.
3. Barcode first — if an EAN comes back, keep it; it's the best thing you have.
4. Then OCR, and extract scale, brand and a candidate number from the text blocks.
5. Match against your existing kits first. A confident match offers "this looks like *Grumman F-14D Tomcat* — attach the photo to it?"
6. No match → prefill the new-kit form with whatever was found, all fields editable, with a quiet note saying it came from the photo.
7. For the Scalemates link, reuse what's there: open their search with the EAN or brand plus number, you pick, you paste.
8. Optionally store the EAN on the model — a new column and a 4 → 5 migration — so a box never needs rescanning.

Worth doing in that order, too: steps 1–4 give you most of the value and can't break anything that already works.
